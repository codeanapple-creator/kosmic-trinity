Build a complete **payment-success → birth-details → Google Calendar booking** workflow for the **KosmicTrinity** website.

## Objective

When a customer successfully completes payment, they should NOT immediately be sent to the normal homepage.

Instead, the customer should be redirected to a dedicated **Thank You / Booking Details** page where they enter their birth details.

After the customer submits the birth details successfully, the system should generate/provide a **Google Calendar booking link** for their KosmicTrinity session.

The entire flow must be reliable, secure, mobile-friendly, and production-ready.

---

## 1. Payment Success Flow

Assume the website already uses **CCAvenue** for payment processing.

Flow:

1. Customer selects a KosmicTrinity session.
2. Customer proceeds to CCAvenue payment.
3. Customer completes payment.
4. CCAvenue sends the payment response to the backend.
5. Backend verifies that the payment was genuinely successful.
6. Store the successful transaction in the database.
7. Generate a unique booking/order reference.
8. Redirect the customer to:

`/thank-you`

Do NOT consider a client-side redirect alone as proof of successful payment.

The backend must verify the payment response before allowing the customer to proceed.

# 6. Google Calendar Integration

After the birth-details form is successfully submitted:

1. Validate the booking.
2. Confirm that paymentStatus = SUCCESS.
3. Create the Google Calendar event using the Google Calendar API.
4. Save the generated event ID in the database.
5. Save the Google Calendar event link.
6. Show the customer the booking confirmation.

IMPORTANT:

Do not expose Google API credentials, service-account credentials, client secrets, or access tokens in frontend code.

All Google Calendar API operations must happen securely on the backend.

# 8. IMPORTANT — Session Timing

Do not randomly create a calendar time.

The application should use the actual KosmicTrinity session availability.

Create a configurable admin setting for:

* Session date
* Session start time
* Session duration
* Time zone
* Available slots

Default time zone:

`Asia/Kolkata`

If the business already has a session/slot-selection system, use that existing slot instead of creating a new one.

---

# 9. Prevent Double Booking

This is extremely important.

Before creating a Google Calendar event:

1. Check whether the booking already has a Google Calendar event.
2. If an event already exists, do NOT create another event.
3. Return the existing calendar link.

This makes the process idempotent.

For example:

If the customer refreshes `/thank-you` or submits the form twice, the system must NOT create two calendar events.

Use:

`bookingId`

or

`paymentTransactionId`

as a unique identifier.

# 12. Error Handling

If payment is successful but the customer closes the browser before entering birth details:

The booking must remain saved.

When the customer returns using their booking link, they should be able to complete the birth details.

If birth details are saved but Google Calendar creation fails:

Do NOT lose the customer's data.

Show:

"We received your birth details, but we're temporarily unable to create your calendar booking. Your information has been saved and our system will retry automatically."

Implement a retry mechanism.

3. Backend verifies successful payment.
4. Customer reaches `/thank-you`.
5. Customer enters:

Build this as a **production-ready feature**, not a mockup or demonstration. After implementation, test the complete payment → birth details → Google Calendar flow and clearly report any configuration values or API credentials that still need to be added in Replit Secrets.
